# Runtime validation and comparative benchmark assignment

Work only in /tmp/ff-reconcile. Preserve every pre-existing user change. Do not copy production Java changes to the original checkout, commit, push, deploy, or contact any production server.

The goal is real, reproducible runtime evidence for Fabric-Folia and a fair comparison against the publicly distributed Fabrolia binary. Do not inspect, copy, port, translate, or derive code from Fabrolia GPL source. Testing an unmodified publicly released binary as a black-box reference is permitted. Keep its downloaded artifact, logs and results outside this repository and record its exact source URL, version, SHA-256, Minecraft version, loader/API/Java requirements and license metadata.

First inspect the existing QA harness and prior reports. Build Fabric-Folia and run the full available unit suite on the reconciled tree. Record exact command, commit/tree hash, counts, failures, skipped tests, elapsed time, and machine resource limits. Fix only independently justified defects; coordinate production-code changes with manager/core/runtime agents and add regression tests.

Then create an isolated disposable server instance outside the repository and perform a real smoke boot with the available 26.2 toolchain. This host has 8 CPU threads, 14 GiB RAM and limited free memory: use the smoke profile and a conservative heap, never the full profile or 40-client profile. Confirm Fabric server reaches Done, record all mixin warnings/errors, collect RCON metrics and JFR/jcmd evidence, exercise safe console commands, stop cleanly, and preserve logs/manifests. Do not invent connected clients; report zero unless a real protocol client completes login and stays responsive.

Research the public Fabrolia release/artifact endpoints from README/release metadata, download only the released binary, verify SHA-256, and test it separately in a disposable instance only if its Minecraft version and runtime requirements match this host. Do not assume the moving prod/current ref is a binary artifact; pin a concrete release/asset. If the binary cannot be obtained or its required MC version differs from our 26.2 baseline, report the blocker rather than silently comparing unlike versions.

Benchmark methodology: same hardware, OS, Java build, MC version, seed/world configuration, view/simulation distance, JVM flags, heap, mod list, duration, sampler interval, and workload. Randomize run order or alternate A/B. Do at least three runs per candidate if resource limits allow. Record boot time, MSPT p50/p95/p99/max, TPS, heap/GC, CPU, worker utilization, region count, queue depth and crashes. For a clientless smoke run label it clientless and do not infer player-load performance. A true 40-client comparison must wait for a host with >=32 GiB RAM and a verified native protocol client; do not fake it.

Add scripts only where needed, no comments or docstrings in code. Write a detailed report to tools/freebuff/reports/live-runtime-and-benchmark.md with exact evidence paths, artifact hashes, raw data paths, all deviations, and a verdict that distinguishes tested facts from unverified claims. Report back to manager with concise blockers and next actions.
