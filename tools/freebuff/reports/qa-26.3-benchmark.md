## 1. The gate: no shared Minecraft version

Both mods declare a hard `minecraft` dependency range, and Fabric Loader enforces
it before any mixin is applied:

| Server | Fabric-Folia 0.1.0 (`~26.2`) | Fabrolia 3.2.6-alpha (`~26.3`) |
| --- | --- | --- |
| MC 26.2, loader 0.19.3, API 0.161.0+26.2 | **boots** (`Done (4.711s)`–`(5.241s)`) | **refuses to start** |
| MC 26.3, loader 0.20.1, API 0.166.2+26.3 | **refuses to start** | **boots** (`Done (6.090s)`) |

Refusal evidence (verbatim, `[main/ERROR] Incompatible mods found!`):

```
- Mod 'Fabric-Folia' (fabricfolia) 0.1.0 requires any version between 26.2
  (inclusive) and 26.3- (exclusive) of 'Minecraft' (minecraft), but only the
  wrong version is present: 26.3!
```
```
- Mod 'Fabrolia' (fabrolia) 3.2.6-alpha requires any version between 26.3
  (inclusive) and 26.4- (exclusive) of 'Minecraft' (minecraft), but only the
  wrong version is present: 26.2!
```

Logs: `/tmp/ff263-boot.log`, `/tmp/fab262-boot.log`. Consequence: a same-version
A/B needs either a 26.3 port of Fabric-Folia (production change, out of QA scope)
or a 26.2 Fabrolia build (none published: 3.2.0, 3.2.1 and 3.2.6 all declare
`~26.3`). Nothing is compared and no winner is named.

## 5. Gameplay lane (real protocol client)

Client used: `compat/probe_bot.py` recovered from git history (`1325fdd`), a raw
protocol-776 (26.2) client that performs login → configuration → play and handles
teleport, keep-alive, death and respawn. Local copy only (`/tmp/probe_bot.py`),
extended with an RCON helper and a cross-dimension phase; nothing in the repo was
changed.

| Test | Result |
| --- | --- |
| Login on Fabric-Folia 26.2 | **pass** — `ProbeBot logged in with entity id 6 at (6.5, 114.0, 3.5)` |
| Same-dimension player teleport (RCON `tp`, 256 blocks) | **pass** — `Teleported ProbeBot to 262.5,114.0,259.5`, client applied it, no kick |
| Cross-dimension teleport overworld → nether | **pass** — position applied, advancement `We Need to Go Deeper` fired |
| Return nether → overworld | position applied, but the session then hit a `2762ms / 55 ticks behind` warning and the vanilla anti-float kick (below) |
| Death + respawn | **pass** — `respawned: True` at the teleported position |
| Locomotion / chunk churn by walking | **invalid test** — see below |
| Portal traversal (player-built nether portal) | **not tested** — the bot cannot walk to or stand in a portal |
| Fabrolia 26.3 gameplay | **impossible** — protocol 776 rejected |

Why locomotion is invalid: the same bot against a vanilla 26.2 control (identical
loader/API/properties/seed, mod jar removed) is kicked after ~14 s with
`ProbeBot was kicked for floating too long! … Flying is not enabled on this
server`. The bot does not emulate gravity/ground state well enough for vanilla's
anti-float guard, so walk-based movement, region-boundary crossing and chunk
churn cannot be judged with it. On the modded server the same deficiency showed
up differently (1232 position packets at one spot, no kick) — an interesting
behavioural difference, but **not** a mod verdict, and it is reported as an
observation requiring a real client, not as a defect.

Why 26.3 gameplay is impossible: no 26.3 client exists here. `minecraft-data`
3.119.0 stops at 1.21.11 (so mineflayer 4.39.0 cannot speak 26.x); Azalea HEAD
`0d38e0d` declares `PROTOCOL_VERSION = 776`, `VERSION_NAME = "26.2"`. The 26.3
server confirms the mismatch: `login disconnect: …multiplayer.disconnect.incompatible
… ["26.3"]`.

## 6. Reproducible apples-to-apples protocol

Preconditions (all must hold, else the run is invalid, not "close enough"):

1. Same Minecraft version, loader, Java, fabric-api build, heap, JVM flags,
   `server.properties`, seed and world type for both subjects; fresh world per
   run; identical fresh-instance assembly.
2. Same mod-surface parity: either both run regionized/parallel execution of the
   same feature set, or both explicitly run vanilla-style execution. Record which.
3. Same workload file for both, with an idle phase and a loaded phase; more than
   one run per subject (n ≥ 3) so variance can be reported.
4. Same client if any client is used (a real vanilla client or a bot that passes
   the vanilla control run first).
5. Metrics that both sides expose; if a side's command surface is broken, the
   run yields no engine-internal numbers and the comparison is TPS/heap-only.

Per-run procedure (already implemented in `tools/freebuff/qa/`):

```
assemble_server.sh --server-bundle <jar> --loader <jar> --fabric-api <jar> \
  --mod-jar <mod> --config <yml> --run-id <id> --seed 4242424242
run_bench.sh --instance <dir> --execute --clientless-only \
  --run-id <id> --duration 180 --interval 5
```

Record per run: `Done (…)` and wall time, mod list, mixin errors and cancellations,
TPS mean/min/p50/p95/max from gametime deltas, heap last/max (jcmd), JFR file and
size, `/proc` CPU% and RSS, stop result, crash reports, leftover ports/processes.
Exclude warm-up samples; report p50/p95 rather than only the mean; keep raw logs.

Acceptance rule for a claim: same version gate passed (both boot on one MC
version), n ≥ 3 per subject, non-overlapping TPS/MSPT distributions or a stated
effect size, and no config asymmetry. Otherwise report "measured, not compared".

## 7. Limitations

- One Fabrolia run (n = 1) and no Fabrolia config parity: its numbers are a
  boot/workload sanity record, not a benchmark result.
- Fabric-Folia engine metrics unavailable (L1) and Fabrolia has no equivalent
  surface, so no MSPT/worker/region comparison is possible.
- Gameplay evidence covers teleport, cross-dimension teleport and respawn only;
  locomotion, portals, mounts, inventory and packet latency remain untested.
- Harness workarounds applied identically to all instances (see §8) and a private
  harness copy was used for the 26.3 lanes.

## 8. Harness deviations (QA-side only, outside the repository)

- `tools/freebuff/qa` copied to `~/.cache/ff-qa-evidence/qa26`; `qa_lib.sh`
  patched to accept `MINECRAFT_VERSION` / `LOADER_VERSION` / `FABRIC_API_VERSION`
  / `MOD_VERSION` / `MOD_JAR` / `REPO_ROOT` from the environment because the
  original pins 26.2 through `gradle.properties`.
- Every instance received `eula.txt` and a `loader-deps.txt` (ASM 9.10.1 ×5 +
  sponge-mixin 0.17.3) with a six-line `start.sh` append, because the assembled
  classpath omits them (`ASM not detected on the classpath` otherwise).
- `ff-vanilla-262` is a control instance whose mod jar was deleted after
  assembly; `qa/control-note.txt` records it.
- The harness names the installed jar `fabric-folia-<MOD_VERSION>.jar` even when
  the subject is Fabrolia; the manifest hash (`42678345…`) is the identity.

## 10. Verdict

Fabric-Folia 0.1.0 and Fabrolia 3.2.6-alpha are **mutually exclusive on
Minecraft version** (26.2 vs 26.3, enforced by Fabric Loader in both
directions). Both were booted, sampled and stopped cleanly in their own lanes,
and real player teleport/respawn was exercised on Fabric-Folia with a protocol
client. No same-version pair, no 26.3 gameplay client and no configuration
parity exist, so **no performance or gameplay comparison is claimed and no
winner is named**. Unblocking requires a 26.3 Fabric-Folia build (or a 26.2
Fabrolia release) plus a client that can speak that version and passes the
vanilla control.
